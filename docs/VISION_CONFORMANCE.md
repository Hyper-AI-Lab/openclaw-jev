## Method

1. **Per theme (12 themes).** An auditor judged every requirement against the code and the live system. An adversarial skeptic re-checked each verdict and each piece of evidence. An adjudicator settled every disagreement, re-probing where needed, and set the home work package (WP) of each gap.
2. **Completeness critic.** A final pass read every founding source in full against the inventory and added the requirements that no row covered (R-145 to R-149).
3. **Triage.** Every gap and every new finding was mapped to a WP of the hardening programme: an existing WP, a scope extension of one, or one of two proposed new WPs (WP-38, WP-39).
4. **Kirill's decisions bind.** A requirement replaced by a later decision of Kirill's is SUPERSEDED with the decision cited. A supersession that only the audit proposes is marked "proposed" until Kirill confirms it.

## Verdict legend

| Verdict | Meaning |
|---|---|
| MATCH | The requirement, as written or as Kirill adjusted it, holds in code and, where it applies, on the live system. |
| PARTIAL | The core holds; at least one named part does not. The evidence column says which. |
| MISMATCH | A mechanism exists, but it does not do what the requirement says. |
| MISSING | Nothing implements the requirement. |
| SUPERSEDED | A later decision by Kirill replaced the requirement (cited). "(proposed)" means the audit proposes it and Kirill has not yet confirmed it. |

No row is UNVERIFIED, and no supersession is still proposed: Kirill ruled on each one at the Phase A checkpoint.
